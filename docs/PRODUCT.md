# VoiceDeck 产品文档

## 1. 产品定位

VoiceDeck 是一款面向 macOS 的按住说话桌面助手。用户在任意应用中通过全局快捷键发起语音输入，获得与当前任务连续相关的 AI 对话；需要时可将当前最上方窗口的截图作为上下文一并发送。

产品的核心价值不是替代完整聊天客户端，而是把“提出一个与眼前工作有关的问题”缩短为一次自然的快捷键操作。它应当在不打断用户当前工作流的前提下，可靠地完成录音、转写、理解、回答和上下文管理。

### 目标用户

- 高频使用 Mac 完成写作、研究、编码、会议和运营工作的知识工作者。
- 需要快速把屏幕内容和口述问题交给 AI 理解的用户。
- 偏好语音交互，但仍需要可回顾、可管理的本地对话历史的用户。

## 2. 已实现能力

当前版本已经具备以下能力：

- 原生 macOS SwiftUI 桌面应用与对话历史侧边栏。
- 全局按住说话快捷键：`Option + Z` 按下开始录音、松开提交。
- 截图上下文快捷键：`Option + X` 截取当前最上方可共享窗口，并在下一次语音请求中作为上下文使用。
- 录音与截图期间显示不抢焦点的浮窗反馈。
- 可选择系统输入设备，降低因默认麦克风错误导致的录音问题。
- 使用阿里云百炼 Qwen Omni Realtime 完成当前的实时语音输入、回答生成与语音播放。
- 支持设置回复音色及上下文延续时间。
- 对话可新建、重命名、置顶、归档、删除，并持久化保存在本机。
- DashScope API Key 存于 macOS 钥匙串，不写入仓库或应用配置文件。
- 提供屏幕录制权限的请求与失败提示路径。

## 3. 当前问题与非目标

### 当前问题

- 屏幕录制权限受 macOS TCC、应用 Bundle ID、重启应用及窗口可共享性影响，授权后的实际截图成功率仍需系统化验收与诊断。
- 当前截图上下文只在请求链路中使用，没有作为可浏览的结构化附件持久化到对话中。
- 当前浮窗只表达录音或截图状态，尚未实时呈现识别出的文字。
- 对话能力绑定在单一 Qwen Realtime 服务上，无法由用户选择 OpenAI、Kimi、GLM、MiniMax 等对话模型提供商。
- 现有界面验证了核心交互，但视觉层级、空状态、错误恢复和附件浏览仍偏向原型，尚未达到正式发布质量。

### 非目标

- 不将 VoiceDeck 做成通用团队协作、知识库或多端同步产品。
- 不承诺绕过 macOS 的麦克风、屏幕录制、钥匙串或系统隐私机制。
- 不在下一版本内自建语音识别模型；语音识别可继续使用现有实时服务。
- 不自动上传用户的完整屏幕、所有历史或本机文件；截图只在用户显式发起的快捷键流程中处理。
- 不在未明确说明能力、价格和数据策略前，把第三方模型供应商设为隐式默认项。

## 4. 核心用户流程

### 流程 A：纯语音提问

1. 用户在任意前台应用中按住 `Option + Z`。
2. VoiceDeck 显示轻量浮窗，开始采集选定麦克风的音频。
3. 浮窗实时展示不断更新的识别文本，用户可据此确认系统听到了什么。
4. 用户松开快捷键，VoiceDeck 提交语音、更新对话并生成回答。
5. 回答写入当前会话；在支持语音播放时播放回复音频。

### 流程 B：带窗口上下文的语音提问

1. 用户把希望 AI 理解的应用窗口置于最前方。
2. 用户按住 `Option + X`，VoiceDeck 同时开始截图和录音，并显示统一的轻量浮窗。
3. 成功取得截图后，浮窗以小状态提示确认截图已附带；截图失败不应阻断语音输入，需给出可操作的失败原因。
4. 用户松开快捷键后，系统将语音转写、截图附件和近期会话上下文一并交给所选对话模型。
5. 对话中展示可点击的截图缩略图；点击可查看大图、来源应用和时间。

### 流程 C：配置与恢复

1. 用户在设置中选择输入设备、语音回复选项和对话模型提供商。
2. 用户只在首次保存新密钥、替换密钥或钥匙串需要授权时处理系统弹窗；日常使用不重复请求钥匙串授权。
3. 当录音、截图或模型连接失败时，界面说明失败类别、下一步操作和是否可重试，不吞掉语音或附件状态。

## 5. 下一版本明确范围

### 5.1 实时转写浮窗

- 录音浮窗实时显示稳定且可读的识别文本，支持中间结果更新与最终文本确认。
- 浮窗保持无边框、黑白高对比、非抢焦点和固定尺寸约束；文本过长时采用截断或滚动策略，不挤压关键录音状态。
- 截图流程也使用一致的轻量浮窗反馈，而非单独的突兀提示。

### 5.2 对话模型提供商

- 将“语音识别/实时语音链路”和“对话生成链路”分离。
- 首期支持可配置的 OpenAI、Kimi、GLM、MiniMax，以及现有 Qwen 对话能力。
- 使用统一的提供商抽象描述模型、认证、流式响应、文本能力和图像理解能力。
- API Key 按提供商安全保存；没有配置的提供商不得参与请求，也不应在后台反复触发钥匙串授权。

### 5.3 图像附件

- 建立独立附件数据模型和本地附件存储，消息只保存引用与元数据，不把大图直接塞入会话 JSON。
- 截图作为用户消息附件持久化，聊天列表显示缩略图，点击可查看大图。
- 附件应带有 MIME 类型、尺寸、来源窗口/应用、创建时间与可清理标识。
- 删除会话或附件时进行可恢复且一致的本地清理；请求模型时只上传用户明确附带的图像。

### 5.4 `Option + X` 截图并语音

- 将 `Option + X` 改为与 `Option + Z` 一致的“按住说话、松开提交”交互，同时并行截取前台窗口。
- 截图是可选上下文：截图失败时继续完成语音对话；录音失败时不应把截图误发送为独立提问。
- 菜单、设置、浮窗与帮助文案统一写为 `Option + X`，不保留旧的 `Option + Shift + Z` 提示。

### 5.5 发布级 UI

- 将现有演示型页面收敛为一致、可扫描的桌面工作界面：稳定的侧栏、会话区、输入状态和设置层级。
- 处理加载、空状态、权限缺失、网络失败、未配置模型和附件上传失败。
- 图标、间距、字号、颜色、悬停和键盘操作遵循 macOS 习惯，避免装饰性卡片堆叠。
- 对话附件、模型选择、输入设备和隐私提示拥有明确可发现但不过度打扰的入口。

## 6. 数据与隐私原则

- 最小化采集：仅在用户按住快捷键或明确执行截图操作时采集音频或窗口图像。
- 本地优先：对话历史、附件索引和用户偏好默认保存在本机；附件原始文件放在应用专属目录并与消息引用关联。
- 密钥隔离：API Key 只写入 macOS 钥匙串；应用界面不回显已保存密钥，也不在日志、崩溃报告或仓库中记录密钥。
- 明确出站：音频、文本和附件仅发送给用户选择且已配置的模型提供商，用于完成当次请求。
- 可解释失败：权限、设备、钥匙串、网络、认证、模型能力和窗口不可共享等错误应当区分呈现。
- 可删除：用户删除会话或附件后，产品应同步删除相应本地引用与可安全清理的附件文件。

## 7. 验收标准

### 语音与浮窗

- 按住 `Option + Z` 时，浮窗在可感知的短时间内出现，且不抢占当前应用焦点。
- 录音期间浮窗持续显示实时识别文本；松开后最终文本与发送内容一致或有明确差异标识。
- 选择输入设备后，应用使用该设备录音；设备不可用时给出可恢复提示。

### 截图与附件

- 按住 `Option + X` 时同时开始截图和语音输入，松开后作为同一条用户消息发送。
- 获得屏幕录制授权并重启应用后，可截取普通前台窗口；无法截取的窗口会给出具体原因。
- 截图附件在会话重启后仍可显示缩略图和大图，且不随会话 JSON 膨胀到不可接受的大小。
- 截图失败不阻塞语音请求，且不会产生没有用户文本的错误消息。

### 模型提供商

- 用户可选择已配置的对话模型提供商和模型；未配置的提供商不能发起请求。
- 同一份标准化对话请求可包含文本、历史和图像附件，并由具备视觉能力的提供商正确接收。
- 供应商错误能区分网络、认证、限额、模型不支持图像与服务端错误。
- 日常读取已保存密钥不重复请求钥匙串授权；仅保存或替换密钥时可能触发系统授权。

### 发布质量

- 新功能具备数据模型、存储与提供商抽象的单元或可执行验证测试。
- `swift build` 通过，核心配置和模型请求编码测试通过。
- 不在版本库、应用包或日志中包含真实 API Key、截图附件或用户会话数据。

## 8. 版本划分

### v0.1：语音交互基础（已完成主体）

- Qwen Realtime 语音输入、回答与播放。
- 全局快捷键、输入设备选择、对话历史与基础截图上下文。
- 本地钥匙串密钥管理及基础权限引导。

### v0.2：可靠上下文与多模型基础（当前开发范围）

- 对话与附件数据模型升级。
- 本地附件存储、会话引用与清理策略。
- 对话模型提供商抽象、配置模型与测试基座。
- 为截图附件展示和多提供商设置预留稳定接口。

### v0.3：完整交互与发布体验

- 实时转写浮窗。
- `Option + X` 截图并语音的一体化流程。
- 对话内图像缩略图和大图预览。
- 供应商选择与配置界面、错误恢复与发布级 UI 打磨。
- 端到端权限、设备、网络与多模型验收。
